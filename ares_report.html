Key findings

The application can be fully compromised by an unauthenticated attacker. A SQL injection on the login form grants administrator access without credentials, and a separate broken-access-control flaw means any logged-in user can already reach admin data server-side — so the two reinforce each other. A reflected XSS adds session-theft against individual users. Overall risk: Critical.

SQLi login→admin session→all users & orders+XSS session theft

Findings in detail

CriticalCVSS 9.8VULN-001 · CWE-89
SQL injection on the login endpoint
POST /rest/user/login — parameter: email
CVSS 3.1
9.8 Critical — AV:N/AC:L/PR:N/UI:N/S:U/C:H/I:H/A:H
Found by
SQLi Validation Agent — Qwen3.6-27B-OBLITERATED (from Recon Agent's endpoint map)
What it is
The login handler builds its SQL query by concatenating the submitted email straight into the statement, so input becomes executable SQL rather than data.
Discovery
Recon Agent mapped the endpoint; the SQLi Validation Agent then submitted a boolean payload in the email field and observed a successful login with no valid password.
Proof of concept
# email field:
' OR 1=1--
# resolves to:
SELECT * FROM Users WHERE email = '' OR 1=1--' AND password = '...'
Why it works
The trailing -- comments out the password check, and OR 1=1 makes the WHERE clause always true. The query returns the first user row — the administrator.
What it enables
Full authentication bypass. An attacker logs in as any user without credentials, obtains a valid session/JWT, and inherits the administrator's privileges — the entry point to every other account and order.
Remediation
Use parameterized queries / an ORM binding for every user input; never concatenate. Add least-privilege DB accounts and generic auth error messages.
MediumCVSS 6.1VULN-002 · CWE-79
Reflected cross-site scripting in product search
GET /#/search — parameter: q
CVSS 3.1
6.1 Medium — AV:N/AC:L/PR:N/UI:R/S:C/C:L/I:L/A:N
Found by
XSS Agent — Qwen3.6-27B-OBLITERATED
What it is
The search term is written back into the results view without output encoding, so an attacker-controlled value is parsed as HTML/JS in the victim's browser.
Discovery
The XSS Agent submitted a marker payload in q and confirmed it executed in the rendered page rather than being displayed as text.
Proof of concept
/#/search?q=<iframe src="javascript:alert(document.domain)">
Why it works
The value reaches an unsafe DOM sink (bound to markup rather than text) with no sanitization or Content-Security-Policy to block inline execution.
What it enables
Arbitrary JavaScript in the victim's session: session/JWT theft, actions performed as the victim, credential phishing on a trusted origin. A crafted link is enough to trigger it.
Remediation
Contextually encode all reflected output, bind values as text not HTML, and deploy a strict CSP (script-src without unsafe-inline).
HighCVSS 8.1VULN-003 · CWE-284
Broken access control on the admin area
GET /#/administration and its backing API
CVSS 3.1
8.1 High — AV:N/AC:L/PR:L/UI:N/S:U/C:H/I:H/A:N
Found by
Access Control Agent — Qwen3.5 (14B), escalated to Qwen3.6-27B for confirmation
What it is
Authorization for the admin section is enforced only in the client. The backing API returns administrative data to any authenticated user, regardless of role.
Discovery
The Access Control Agent navigated straight to the admin route with a non-admin session and called its API directly; the server responded with admin-only data.
Proof of concept
# as a normal (non-admin) user:
GET /rest/admin/application-version
GET /api/Users        # returns every user record
Why it works
The route guard runs in the SPA only; the server never re-checks the caller's role. Hiding a button is not access control.
What it enables
Any logged-in user reaches administrative functions and reads all users and orders — a direct confidentiality and integrity breach across every account.
Remediation
Enforce role checks server-side on every privileged endpoint; deny by default. Treat client-side guards as UX only, never as a security boundary.

Remediation — priority order

  1. Parameterize the login query — closes the auth bypass (VULN-001)
    effort: low · fix first
  2. Enforce server-side role checks — stops admin data exposure (VULN-003)
    effort: medium
  3. Encode output + add a strict CSP — neutralizes reflected XSS (VULN-002)
    effort: low
  4. Add regression tests & re-scan — confirm each fix, track over time
    effort: low
